# Desktop host bridge

`await createDesktopHost()` opens a native-owned session for the local main application WebView. It implements the shared `HostClient` using bounded native commands and binary chunk IPC. The composition root calls `dispose()` when replacing the adapter; destroying the window also closes its native sessions. Ordinary builds use the native composition root’s fixed OpenAI global, OpenAI US, OpenAI Europe and Anthropic global destination registrations. JavaScript cannot register arbitrary origins through this interface.

Native `Destination` values bind provider, account, destination and transport IDs to an origin, exact allowed paths/methods, allowed request headers, permitted query parameter names per route (Anthropic model listing only), credential injection format and product privacy class. Query values are bounded to 256 characters without control characters and encoded by Rust; unregistered names are refused before dispatch. HTTPS is required except for explicitly registered loopback HTTP. Caller URL escapes, unregistered routes, credential header overrides and redirects are rejected. Environment/system proxies and automatic retries are disabled; transport classification therefore describes the configured direct route. No canonical SQLite access exists in this adapter.

## Regional OpenAI registrations

The native-owned [registry](../../src-tauri/src/registered_destinations.rs) registers `https://us.api.openai.com` and `https://eu.api.openai.com` separately from global OpenAI. Each has a distinct destination/transport binding, exact GET `/v1/models` and POST `/v1/chat/completions` routes, and an independently bound Keychain credential. These are available as `openai-us` and `openai-eu` in the desktop connection list.

Regional capability metadata is derived only when the complete binding, origin, route set, authentication scheme and privacy declaration match the fixed native review. It identifies the reviewed dated GPT-4.1 mini model, Chat Completions endpoint and text/image modalities. It does not assert that a credential's organization/project has regional eligibility. The shared provider settings layer obtains the user's credential-specific eligibility confirmation before publishing a configured regional adapter; see [ADR 0023](../../../../docs/decisions/0023-regional-processing-evidence.md).

The [regional native proof](../../../../tests/hosts/results/tauri-native-regions-macos-26.6.2.json) reads unchanged production registration metadata through the actual Rust/WebView boundary. It separately dispatches synthetic model-list and Chat Completions requests through cloned loopback registrations with distinct bindings and **no regional evidence**. It checks byte preservation, credential separation and pre-dispatch refusals. No live regional provider request, account eligibility, or physical processing location is proven by that fixture.

## Credentials

The current native secret backend is **macOS Keychain only**. `createDesktopHost().secretStore` reports backend availability and an actionable reason; an absent/locked/denied store produces a typed error instead of plaintext fallback. Windows and Linux secret-store integrations remain unimplemented and are not covered by the macOS evidence.

The actor serializes OS-store operations on blocking worker threads, admitting at most four calls without an unbounded waiting queue. Secret values remain native after entry and have no general JavaScript read API. Keychain records include the provider/account binding and the concrete credential origin/header format. Reusing a binding ID with another origin cannot reuse its old credential. Handles can be retained in local connection metadata and survive process restart; raw credentials cannot enter canonical history or archives.

Replacement writes a new entry, removes the old entry, and returns a new handle. Deletion and replacement cancel active requests using that credential. Temporary native secret strings/buffers are zeroized and credential headers are marked sensitive; copies made inside system/network libraries are outside that guarantee. Store failures use redacted fixed messages.

OS keychain transactions cannot be interrupted after dispatch. `cancel` provides concrete cancellation for registered HTTP operations and staging; untracked requests, including keychain calls, conservatively report `unknown_outcome`/`may_have_occurred`. Callers must await a keychain operation's result and reconcile connection metadata rather than treating cancellation or window closure as rollback. Crash recovery for interrupted connection-metadata/keychain updates remains a later integration gate.

Dependencies were checked against official documentation on 2026-09-08: [keyring-core 1.0](https://docs.rs/keyring-core/latest/keyring_core/), [Apple store 1.0.2 with explicit `keychain` feature](https://docs.rs/apple-native-keyring-store/latest/apple_native_keyring_store/), and [reqwest 0.13.4](https://docs.rs/reqwest/latest/reqwest/). Cargo.lock records resolved packages. `reqwest` uses explicitly enabled native TLS/stream support, normal certificate validation and no ambient proxy route. Tauri's official [binary command API](https://v2.tauri.app/develop/calling-rust/) carries transfer payloads; the TypeScript dependency is pinned to `@tauri-apps/api` 2.11.1.

## HTTP and transfers

The native service admits four HTTP operations across all sessions, four sessions, sixteen staged transfers, and four unacknowledged reads per response. Each IPC chunk is at most 64 KiB. Request staging is currently limited to 8 MiB per transfer and a 16 MiB aggregate retained staging/request-body budget; native upstream chunks have a separate 1 MiB bound per active response. These bounds do not describe total process memory, TLS internals or kernel buffers.

Staged writes check exact sequence, offset, final state, declared size and SHA-256 before dispatch. Acknowledgements check the exact sequence/end offset. Input and output transfer IDs belong to their native session. Release, final acknowledgement, cancellation and window teardown drop request/response resources; producers cannot enqueue unlimited IPC events. Response status and safe headers are preserved for provider normalization, while the body stays incremental.

Native `connectMs` bounds connection establishment, `idleMs` bounds network/read progress and `totalMs` bounds the request lifetime, including consumer stalls. Cancellation after dispatch reports possible external effects; it cannot establish that a provider did no work or charged nothing. Network and deadline failures use `IO_ERROR`, user cancellation uses `CANCELLED`, and no generation POST is automatically retried.

## Native files and large exports

`chooseFiles` opens a native panel through Rust-only `tauri-plugin-dialog` 2.7.3. JavaScript receives opaque session-owned file IDs, names and sizes; it cannot supply or read filesystem paths. At most 256 file grants and sixteen native file readers are retained across the host. `openFileTransfer` reads the already-opened regular file using positional reads, preserving independent reader offsets. Each read is at most 64 KiB with four acknowledgement credits. Size/modified-time changes reject further reads; this detects ordinary edits but is not a filesystem snapshot against concurrent in-place writes. Release of a file also closes its associated readers. Filters use an explicit MIME-to-extension registry; unsupported filters return an actionable error instead of silently broadening selection.

Files dropped onto the WebView arrive as platform file objects, not native paths. The TypeScript bridge adopts them through `adoptFiles` under the same 256-handle bound, serves them in 64 KiB positional slices with one credit, and releases them with their handles; native dialog selections keep their native readers. `tauri.conf.json` sets `dragDropEnabled: false` so HTML5 drops reach the interface ([Tauri window configuration](https://docs.rs/tauri-utils/2.9.3/tauri_utils/config/struct.WindowConfig.html), read 2026-09-09). This path is typechecked and shares the shared app's browser proof of the drop-to-attachment flow, but no native Tauri window has exercised a drop yet; that remains a host gate.

`file_save` staging uses anonymous `tempfile` 3.27.0 files with incremental SHA-256 and explicit final length/hash verification. It has a 1 TiB host-owned retained disk budget and sixteen staged file transfers; actual filesystem quota can reject writes earlier. The budget accounts bytes written, not a reservation of future physical space. File IO admits at most four blocking operations without a waiting queue. A staged file advertises one pending write at a time; reads retain their four-credit window. Release, cancellation and session closure drop anonymous staging handles. On the tested macOS filesystem, their directory entries are already unlinked while open. Provider-request staging retains its separate 8 MiB memory cap and 16 MiB aggregate budget.

`saveFileTransfer` requires verified staging before opening its save panel. After selection it copies in 64 KiB pieces to a private sibling temporary file, verifies the copied digest, syncs file contents, checks for a changed destination, and atomically replaces the selected regular destination. Symlink destinations are rejected. On Unix it also syncs the containing directory; failure after replacement reports `UNKNOWN_OUTCOME`, since the new bytes may already be visible. Export preparation needs space for both staging and the destination-side temporary copy. The caller releases staging after success or abandonment.

Cancellation before the replacement step preserves existing destination contents and reports `not_dispatched`; once commit begins it conservatively reports `may_have_occurred`. A kernel filesystem operation already in progress cannot be forcibly interrupted, so cancellation is observed between bounded IO steps. Cancelling a dialog request ignores later selection but does not dismiss the OS panel; close that panel before another can be opened. Native dialog admission remains held until its callback returns.

Normal errors/cancellation clean sibling temporary files. A forced process kill during destination preparation can leave a private `.quixi-export-*` sibling; automatic recovery/removal requires a future ownership journal and is not implemented by deleting arbitrary matching files. Anonymous staging does not have this named-file recovery problem on tested macOS. Saving is tested on the local macOS filesystem; network filesystems, crash/power-loss recovery, concurrent destination replacement races, Windows/Linux save durability and signed-app permissions remain separate gates.

The [official dialog API](https://v2.tauri.app/plugin/dialog/), [temporary-file ownership](https://docs.rs/tempfile/3.27.0/tempfile/fn.tempfile.html) and [atomic persist/durability semantics](https://docs.rs/tempfile/3.27.0/tempfile/struct.NamedTempFile.html#method.persist) define these implementation boundaries. The optional AppKit bindings used to observe/cancel test panels are enabled only by `host-proof`; production does not automate dialog choices or gain frontend filesystem-plugin permissions.

## Implemented evidence and remaining gates

The [native host proof](../../../../tests/hosts/run_tauri_native_host_proof.py) bundles this exact TypeScript bridge into an opt-in `host-proof` build and runs it in a real macOS Tauri WebView. It uses disposable synthetic keychain entries and controlled loopback HTTP endpoints. Evidence includes replacement/removal, bound native credential injection, binary upload/download, cross-session isolation, credit limits, cancellation and observed upstream disconnects, origin-retarget rejection in another process, and credential survival across process restart. The runner always attempts cleanup restricted to its own synthetic keychain service.

The [large-file proof](../../../../tests/hosts/run_tauri_native_file_proof.py) transfers a 256 MiB synthetic file through the real Rust/WebView boundary, verifies export SHA-256, cancellation preserving an existing destination, bounded chunk credits and complete normal cleanup. Its native-process RSS sampling excludes WebKit/GPU memory. A separate `--dialogs-only` proof actually presents macOS open/save panels and cancels them through AppKit sheet callbacks; it does not automate or claim a human selection/overwrite-confirmation flow.

The clipboard capability and `writeClipboardText` are served by the WebView's page clipboard from the TypeScript bridge and have not been exercised in a native window. OAuth and notifications remain unavailable. Connection-metadata/keychain reconciliation, export crash recovery and broad platform/provider support remain open. This does not complete plan 05 or establish a platform release claim. The existing `storage-proof` feature keeps its own entry point and commands and does not activate native host test mechanics.
