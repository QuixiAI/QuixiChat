# PDF cases from 1 to 1,000+ pages

Plan [24](../plans/24_validate_scale_and_release_hosts.md) task 6 ("run PDF
cases from 1 to 1000+ pages, including malformed, encrypted, multi-column,
scanned, and image-heavy inputs; report memory, extraction speed, time to
FTS, cancellation, and resume"). This page maps each requested case to the
retained evidence produced under plan [14](../plans/14_build_document_extraction.md)
and the [production PDF performance harness](../../perf/documents/README.md);
it adds no new measurement. All runs: macOS 26.6.2 (arm64), Playwright
Chromium and WebKit, PDF.js 6.3.289, synthetic redistributable fixtures
(`packages/documents/tests/fixtures`, generated by `generate_fixtures.py`).

## Cases

| Requested case | Fixture | Outcome and evidence |
| --- | --- | --- |
| 1 page | `pages-1.pdf` | Extracted and indexed in both engines ([extraction-browser.json](../../packages/documents/tests/results/extraction-browser.json): 111 ms Chromium, 100 ms WebKit through the isolated package; 0.226 s / 0.383 s end to end through the production pipeline). |
| 100 pages | `pages-100.pdf` | 879 ms / 1,207 ms isolated; 7.2 s / 6.2 s end to end with the first page indexed at 395 ms / 185 ms. |
| 1,000 pages | `pages-1000.pdf` | 5.9 s / 9.9 s isolated; 54.9 s / 30.7 s end to end, first page indexed at 778 ms / 317 ms, all 1,000 chunks indexed and `ready` afterwards. |
| 1,000+ pages | `pages-1001.pdf` | Refused with the typed `CAPACITY` outcome in both engines: the declared page limit is 1,000 (`LIMITS.pages`, product §85); nothing is created for the document. |
| Malformed | `malformed.pdf`, `invalid-utf8.txt` | Typed `PARSE_FAILED` in both engines; supported imports stay usable afterwards. |
| Encrypted | `encrypted.pdf` | Typed `PASSWORD_REQUIRED`; password entry is not claimed. |
| Multi-column | `layout-columns.pdf` (plus `layout-table-code.pdf`, `layout-unsupported.pdf`) | Structured layout proof ([layout-fixtures.md](../../packages/documents/tests/layout-fixtures.md), `npm run test:documents:layout:browser`): column order and table/code blocks recovered, unsupported layouts fall back to reading order with a durable notice. |
| Scanned | `scanned.pdf`, `low-text.pdf` | Reported as possibly scanned with zero text units; OCR is deferred (plan 15). |
| Image-heavy | 31,115,264-byte image-heavy PDF with native text (perf harness) | Completes, publishes and indexes its native-text page in 21.7 s Chromium / 15.6 s WebKit after the SHA-gated range-request fix; no image decoding. |
| Dense text | `dense-page.pdf` (262,145 characters on one page) and the dense 100-page set (15.1 million UTF-16 units) | The single oversized page is refused as `CAPACITY`; the admitted dense set passes eight production cases per engine ([DENSE.md](../../perf/documents/DENSE.md)). |

## Measurements

- **Memory.** Chromium forced-GC captures across parser, extractor, storage
  worker and page isolates ([GC.md](../../perf/documents/GC.md)): after
  collection no isolate exceeds about 5 MiB at any checkpoint; parser growth
  is 0.49 MiB over the dense 100 pages and 1.24 MiB over 1,000 pages.
  Browser-tree RSS is recorded per case in both engines as qualified
  evidence only (Chromium 1,000 pages peaks at 776,944 KiB of a tree that
  includes shared pages). **WebKit heap and native memory remain
  unobserved**: Playwright exposes no WebKit heap sampler and its XPC
  processes fall outside the sampled tree.
- **Extraction speed.** The table above; the 1,000-page index-credit path
  was profiled and reduced from 98.4 s to 27.5 s (Chromium) and 30.1 s to
  11.8 s (WebKit) by the page-credit correction.
- **Time to FTS.** First page publication and first index credit are timed
  per case (305–778 ms Chromium, 161–317 ms WebKit for 1–1,000 pages); the
  page is searchable through the public FTS query before the document
  completes ([persistence-browser](../../packages/documents/tests/persistence-browser/README.md)).
- **Cancellation.** Cancellation after the first indexed page of a fresh
  1,000-page run drains the workflow, terminates both parser workers,
  leaves a durable interrupted state with page 1 retained and indexed and
  unchanged canonical/sync counts (perf harness `cancel-1000`; isolated
  `cancel` case: `CANCELLED` after 2 pages).
- **Resume.** Resume starts the parser at page 2, preserves page 1's
  reference and maps and completes the document (persistence proof,
  `resumed.parserStartPages = [1, 2]`); text resume is refused except at
  the document boundary (`CAPACITY`).

## Not covered

- WebKit heap and native (Tauri) memory attribution.
- Documents above 1,000 pages or 32 MiB are refused by declared limits, not
  measured; raising the limits is a product decision.
- OCR for scanned input (plan 15, deferred).
- Timings are single runs under development load on one machine.
