# Provider export importers

Shared, bounded provider-history normalization for [product §§21–28](../../docs/product.md#21-raw-provider-preservation). The package depends on core contracts and receives a public `StorageClient`; it does not own SQLite, OPFS, provider credentials, inference, or UI state.

## Supported profiles and evidence

- `chatgpt-mapping-observed-2026-v1`: a conversation array with mapping nodes, explicit parents, author roles, string parts, observed image asset pointers, and attachment metadata. `current_node` selects the initial active branch when it resolves. Non-text, unrecognized structured parts stay `ProviderArtifact` references to exact raw bytes. Assistant exports do not fabricate generation attempts or usage.
- `claude-chat-messages-observed-2026-v1`: a consumer conversation array with UUIDs, sender, `chat_messages`, structured text or legacy `text`, attachment metadata, and optional explicit parent UUIDs. A missing parent field uses export order and records a visible warning. Missing active-branch information stays unknown. Unknown blocks stay raw artifacts.
- Original ZIP/ZIP64 containers are retained first. Stored and raw-deflate entries are streamed and verified against declared size and CRC32. Conversation JSON and numbered `conversations-<digits>.json` shards are imported serially; other entries remain in the retained original container. Encrypted, split, ambiguous-path, unsupported-compression and unknown legacy filename-encoding cases fail explicitly. The caller supplies a finite per-entry extraction budget.

These profiles describe independently observed shapes, not a complete official schema. [Fixture provenance](./tests/fixtures/README.md) cites OpenAI/Anthropic export help and a pinned primary maintainer's observed-format evidence. The current fixtures are original synthetic data. **An actual current official-export capture has not been validated by QuixiChat; plan 04's format qualification gate remains open.**

## Entry points

`beginChatgptImport` / `beginClaudeImport` take an injected runtime plus caller-created `operationId`, `runId`, `workspaceId`, `accountScope`, and `recordedAt`. Keep these identities and their payload stable after an unknown outcome. Account scope is an explicit local source-account label, not a secret or a title.

`importChatgptSource` / `importClaudeSource` take `{runId, sourceKey, source?}`. `source` supplies `name`, exact `byteLength`, and an asynchronous bounded `open(start?, end?)` byte range. The end is exclusive; input chunks are at most 1 MiB. A file adapter should stream `File.slice(start,end)`. A durable `sourceKey` identifies this selected source across retries. After raw-byte capture, the original file is unnecessary for resume.

`importProviderZip` takes `{runId, sourceKey, source?, maxEntryBytes}` and selects the provider from the run. ZIP entry descriptors and dependency work live in SQL. It resolves assets by exact archive path, including an observed `sediment://` image asset identifier when that exact entry exists. Ambiguous provider sidecar name mappings are not guessed. Missing bytes retain a logical attachment and warning. A later export can resolve that attachment without changing sealed message parts. Already published attachment bytes remain immutable; changed bytes under an otherwise identical source observation still require explicit revision reconciliation.

`preserveImportFile` retains an original archive or sidecar independently of normalized thread publication. `exportImportReport` emits one bounded newline-delimited JSON record at a time, including source-scoped warnings. The host owns the streaming report destination. `setImportRunState` exposes durable pause/resume/complete controls; it requires a caller-assigned operation ID. Completing a run requires every work group to be terminal. Finishing one source does not automatically finish a run containing several selected sources.

The runtime supplies `storage`, `nextId`, `now`, `cancelled`, and optional progress/asset resolution. One exclusive executor lease protects each run: Navigator Web Locks by default, or an injected `withRunLock` for another host. This lease is independent of the storage-owner lock. Nested archive/JSON calls share the lease; a competing executor receives a busy error. Non-browser tests inject their lease implementation. The UI must stop its active executor before changing run state or discarding work.

## Preservation, identity and restart

Original bytes are hashed incrementally, verified by storage, and registered as immutable `RawObject` records before parsing. A verified retained-file handle pins the original bytes while bounded child ranges serve parser passes. A source decoder, mapping object, thread graph, long string, part manifest or archive directory is never loaded in full by the importer. The parser bounds nesting, keys, number tokens, metadata strings and emitted string fragments. Large canonical text is a verified UTF-8 blob; unpaired escaped UTF-16 is retained as an artifact with a warning instead of silently replacing source characters.

Provider-native thread/message IDs take precedence. Available non-unique timestamps or display metadata do not establish a safe identity by themselves. Where no native thread ID or independently unique stable metadata exists, an explicit content fingerprint is the last resort; it excludes title and mutable display state, records a heuristic warning, and never fills the provider-native source ID field. Changed content without stable source identity may need user reconciliation.

A message observation combines its raw-message digest with its resolved canonical parent and role. A changed observation creates a new sealed message, retains the old message, and links an edit only where the canonical parent and role permit it. New exports preserve local title, tags, routing, context and active-branch state. The original scoped provider mapping remains stable; revision mappings preserve alternate observations. Fingerprints and byte hashes are not disguised as UUIDv4: worker-injected UUIDs are persisted under stable run/work keys.

SQL work rows retain byte locators, parent dependencies, allocated IDs and optimistic checkpoints. Every staging sequence and blob attempt is recorded before its effect. Publication uses the storage engine's hidden import group and atomic canonical/sync marker. An interrupted thread never appears as a partial visible thread. Complete prior threads may remain published if a later source record fails.

A lost raw commit, record-stage, work-resolution or final-publication acknowledgment reuses the original operation and payload. A byte upload interrupted before durable finalization restarts from the selected input; it is not falsely advertised as byte-offset resumable. Its old transfer is found through the control-operation journal and discarded. After verified raw capture, restart reads the retained blob without the original provider account, selected file or search/inference availability. Pausing retains hidden work; a malformed graph is surfaced and retained, not silently skipped. A malformed message record inside an otherwise supported export, such as one with an unsupported or missing author role, is skipped with a `malformed_record_skipped` warning that names its locator and reason: its bytes stay in the retained raw source, it contributes no parts, and its descendants attach to the nearest valid ancestor exactly as a structural node's descendants do. Structural violations of the supported profile still fail the source explicitly. Arbitrary cancellation of already published history is not provided by these import controls.

## Validation and remaining work

Run `npm run typecheck --workspace @quixi/importers`, `npm run typecheck:tests --workspace @quixi/importers`, and `npm test --workspace @quixi/importers`. The SQL harness uses the pinned SQLite WASM artifact with MEMFS; its byte transport is an explicit test double and is not OPFS evidence. It covers exact bytes, branches, revisions, missing and later-resolved attachments, unsupported data, long text, 1,003 parts, a 2,000-message reverse-order generator, bounded controls, pause/restart and lost acknowledgments.

`node --experimental-transform-types packages/importers/tests/browser/run.mjs` runs the independent production worker/OPFS harness in Chromium and WebKit on port 4193, writing `test-results/provider-import-browser.json`. Browser results and their source hashes are evidence only after the report says `passed`.

Remaining plan 04 work includes actual official-export qualification, complete source-format compatibility decisions, richer provider asset-name sidecars and explicit reconciliation for changed published assets. The shared application now provides selection, storage estimates, progress, pause/resume/discard, notice review and report export. The library supports separate raw/canonical/attachment accounting, but does not invent precise storage estimates from compressed input size. Derived indexes are separate and are not created by importing canonical records.

ZIP structure follows [PKWARE APPNOTE 6.3.10](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT); raw deflate uses the host's [WHATWG Compression Streams implementation](https://compression.spec.whatwg.org/).
