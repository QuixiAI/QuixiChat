# Extraction repository integration

`ExtractionRepository` owns only `quixi_extract_*`. Its constructor accepts the existing owner database, synchronous canonical identity lookup, registered extractor/normalizer versions, and a synchronous durable operation-claim callback. The callback must participate in this same database transaction and reject another domain/digest; no external effects or deferred writes are allowed. `initialize()` validates the exact independent derived schema. Failure leaves canonical tables and triggers untouched.

`execute(operation,args)` implements the durable page, progress and source-read operations in core `contracts/extraction.ts`, exported through the core contract and public StorageClient. Inputs are validated and copied before work. Mutations store an exact request digest and original receipt in their transaction; same-ID retry checks the receipt before current writer/page state. Retained receipts/run summaries remain after derived-byte cleanup. The production owner connects these receipts to the schema-10 durable operation-claim registry and global operation status.

The private `publishedSources` seam supplies bounded page enumeration, one published page text source, source-current checks, and publication outbox reads. `acknowledgePublications(revisions)` **must run in the owner's transaction together with FTS dirtiness**; it deliberately does not open a nested transaction. Repeat ACKs are harmless. `page` outbox entries dirty only the new page; `replace` and `clear` signal one document selection invalidation. Production SearchRepository integration fences visible `e:` heads directly with current page/run/attachment/revision, including before delayed outbox drain. New registrations must not go through the legacy document-wide `registerExtractedText` path.

The source digest hashes the original identity, extractor/normalizer versions, page, text SHA and map SHA. Only one bounded page string is assembled/read; map batches are individually hashed and scanned at most 32 rows at a time. Map reads return complete original spans intersecting the requested range, with a revision/range-bound cursor and total serialized response budget; they do not invent clipped PDF byte offsets. Source-map item offsets are UTF-16, and generated spans have a null source. Text reads avoid surrogate splitting and preserve embedded NUL through SQLite JSON quoting.

Publication is currently one synchronous bounded page transaction. The 32,768-map fixture's measured time is in the retained test report (roughly 80 ms on the initial macOS Node run); foreground scheduling/cancellation between preparation slices is an integration review gate. No claim of an interruptible or fixed-wall-time publication call is made. The producer workflow must wait for this page's FTS publication before requesting the next PDF page; this private repository does not itself enforce parser credits or run PDF.js.

`cleanup()` defaults to at most 32 row/queue work units and 1 MiB logical deletion bytes. Indexed cleanup queues avoid scanning the archive for eligible rows. The byte default permits removal of a maximum-size retired page; a caller choosing a smaller budget may need a later larger slice. Abandoned page work must be cleaned before another attempt. Published staging-text duplicates are reclaimed while published maps remain. Clearing or switching a run queues retired pages, immediately fences their visibility, and never changes the original attachment/canonical/sync records.

Initial logical admission is 256 MiB per run and 1 GiB per archive, including retained receipts and estimated metadata reservation. Normal writes leave 64 KiB/run and 1 MiB/archive available for interrupt/clear control receipts (tightened test budgets reserve up to one quarter instead). This prevents payload exhaustion from preventing cleanup. Actual `SQLITE_FULL` may automatically roll back; its original capacity outcome is preserved and exact retry remains possible. These bounds do not include every physical SQLite/FTS overhead or prevent PDF.js decompression/intermediate allocations.

The production owner now supplies stable global claims, public routes/error mapping, bounded idle cleanup and the published-page search adapter. `getPublishedExtractionPage` resolves one current page for restart credit; `advanceExtractionPageIndex` admits at most four shared chunks and reports readiness for that exact page. The documents package supplies a pinned source lease and real PDF producer workflow, with OPFS/browser/owner-loss evidence linked from plan 14. The shared document UI now resolves SearchHits to exact current PublishedPageRefs and reads bounded extracted text. Remaining qualification: foreground finalization latency, varied-layout source navigation and explicit extraction repair UX. `getDocumentExtraction` currently reports persistence progress, not indexed-through-page progress. Scanned/low-text outcomes are supported; OCR is deferred.

Schema2 adds bounded page layout metadata with an exact-v1 guarded transactional
upgrade. Legacy text/maps/checkpoints/receipts retain their bytes and digest
identities; their read outcome is `layout:null`. Supplied assessments use a new
layout-bound source digest, and missing/corrupt metadata fails rather than silently
falling back to legacy absence. The optional publication field is never inserted
into an old request before computing its operation identity. Logical byte admission
and obsolete-page cleanup cover the new metadata. See the
[captured v1 upgrade and frozen-reader evidence](../../../tests/extraction-layout/README.md).
