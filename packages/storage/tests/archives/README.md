# Archive regression evidence

Run `npm run test:storage:archives` from the repository root. The browser fixture builds its own frontend, binds a fresh OS-assigned loopback port, records that origin, and closes its server/browser contexts after the run. It uses the shared `QUIXI_TEST_BROWSERS` selector and does not use provider endpoints or user archives.

Thirteen Node/pinned-WASM tests cover the file-pointer snapshot mechanism, clean logical copy, allocation/cancellation failures, strict TAR/PAX decoding and corrupt graph/schema/journal rejection. The combined [browser report](./results/snapshot-browser.json) records actual Chromium/WebKit OPFS, private repository, production client implementation through the isolated fixture, and shared host/workflow checks. The report is marked running before build and includes timestamps, platform/runtime, origin and source/WASM fingerprints.

The current report passes both engines on canonical schema 12 and includes its complete immutable migration ledger. The positive fixture appends Text across both reserved transport-provenance kinds, preserving NUL/Unicode, source parts, operation history and complete Markdown text. Separate current-schema fixtures preserve attachment exclusions, a summary-purpose generation, typed proposal provenance, the verified frozen input body and edited reviewed text and a fresh branch that clears the applied summary while retaining exclusion choices, its source leaf audit and empty selection, with exact canonical records, reference edges and sync operations. New policy fixtures are created after the genuine schema-8 upgrade proof. The client fixture additionally streams a 9 MiB + 17 byte original, exercises operation identity fences and all eight foreground blob leases, and revalidates a ready restore after owner restart.

`schema-seven.ts` constructs a genuine portable file using immutable migrations 1–7. Since 2026-09-09 the current restore refuses it by name at the schema-8 upgrade floor, read from the raw database before any candidate is cleaned or any schema object compared; the fixture requires that exact refusal, failed schema-validation state, no candidate and unchanged canonical history.

`schema-eight.ts` constructs a genuine schema-8 portable: a database whose objects and ledger are exactly what immutable migrations 1–8 produce, holding the live fixture's canonical records, journal, published import rows and referenced catalog rows, exported by the production portable writer. The current restore upgrades it in the isolated candidate through the fresh-schema copy and reaches a ready state reporting `sourceSchemaVersion: 8` and the current candidate schema; the proof then reads the candidate directly while no owner runs and requires records and journal identical to the source, a current ledger and a clean integrity check, and after owner reopen the ready job revalidates and stays ready before release.

Browser WebKit is not installed Safari or native Tauri. The fixture uses distinct synthetic namespaces and regular persistent contexts because ephemeral WebKit OPFS access failed in this runtime.
